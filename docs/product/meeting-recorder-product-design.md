# meeting-recorder 产品设计文档（逆向还原版）

日期：2026-11-09
性质：**从实现反推**。依据 `docs/plan/meeting-recorder-master-plan.md`（14 个阶段 + 累计约束）、`docs/superpowers/specs/2026-11-09-reliability-first-design.md`、`tools/eval_voiceprint.py`。本仓库没有业务代码，所有"现状"描述来自计划文档，未对照实现核实。
标记约定：【事实】计划里明文写的；【推断】我根据实现反推的产品意图，需要你确认；【缺口】实现里看得出、但产品上没想清楚的地方。

---

## 1. 一句话定位

**一个只在你自己 Mac 上运行的会议录音笔：录下来、转成带时间戳的中文文字稿、分清谁在说话、认出熟人的名字；音频和声纹永不离开本机。**

大模型（发言归纳、面试问题推荐）是可选的后置增强，只在你主动点按钮时，发送文字（及简历图片），不发音频。

## 2. 为什么存在（问题与价值）【推断】

| 现有方案的痛点 | 本产品的回应 |
|---|---|
| 云端转写（飞书妙记、讯飞、Otter）要把会议音频上传 | 录音、转写、说话人区分、声纹全部本地完成（mlx-whisper + sherpa-onnx） |
| 转写出来是一整块文字，不知道谁说的 | 会后说话人区分 + 声纹识别，行格式 `[HH:MM:SS] 张三: 文字` |
| 会议里想标一下重点，事后找不到 | 带时间戳的标注（笔记/重点/注释），并在转写行上打标记、点击定位 |
| 面试要快速出针对性问题 | 面试帮助：职位描述 + 简历 → 按维度和时间分配出题并附答案要点 |
| 录音工具中途卡死，会议白录 | 可信度优先：录音隔离、崩溃恢复、自检页 |

核心价值主张是**隐私 + 可信**，不是"功能最全"。阶段 14 之后的最新一轮设计（reliability-first）整体转向"别丢数据、别乱认人"，印证了这一点。

## 3. 目标用户与场景【推断】

**主用户：一个人（单用户、无账号、无权限体系）**——技术背景较强的中文使用者（需要配 config.toml、跑命令、容忍 `.venv`），在 Mac 上开会/面试。证据：只绑定 127.0.0.1、无认证、无远程访问；README 级 CLI 与 Web 并存；提示语全中文。

**典型场景：**
1. **日常会议记录**：开录 → 实时看转写 → 打标注 → 停止 → 自动生成最终稿 → 回看某人说了什么、让大模型归纳。
2. **面试**：提前维护职位 → 粘贴/截图候选人简历 → 生成 40 分钟面试问题 → 面试时录音并标注 → 会后看候选人的发言归纳。
3. **纯命令行**：`record.py` 录、`transcribe.py` 转，不开浏览器。
4. **事后补救**：录音中途崩溃，打开历史会议补转写。

**非用户**：团队协作、多人共享同一份记录、手机端、Windows/Linux 用户（依赖 `afconvert`、CoreAudio）。

## 4. 产品原则（从约束里提炼）

1. **本机优先，数据不出门**【事实】音频、声纹、标注都在本机；LLM 仅在点击"提交/推荐"时发文字，API Key 只在服务端、不进任何响应/日志。
2. **录音神圣**【事实】说话人区分、声纹、实时转写、大模型任何一个失败，都只警告，不改变录音和基础转写的结果与退出码。
3. **增强可降级**【事实】无声纹、没配 LLM、模型没下载，核心功能照常用，输出与未启用时逐字相同。
4. **诚实标注不确定性**【事实】声纹阈值明确标"未校准"；新设计加高/低双阈值，灰区写"疑似张三"而不是硬认。
5. **一次只做一件事**【事实】同一时间最多一场录音，单 worker，单用户。
6. **文件即真相**【事实/推断】会议是一个目录；"未完成"由文件推导（有 wav 无 transcript.md），不引入 status.json。人类可读、可手工修复。
7. **极简技术栈**【事实】原生 JS、无构建、无 CDN；marked + DOMPurify 固定版本入库。
8. **中文、短句**【事实】面向用户的提示全中文，句子短。

## 5. 产品形态与信息架构

两种入口，共享同一份核心能力：

- **CLI**：`record.py`（录音，`--live` 实时转写、`--speakers N`、`--no-diarize`、`--no-voiceprint`、`--voice-threshold`）、`transcribe.py`（转写）、`enroll.py`（声纹登记）
- **本地 Web 控制台**：`127.0.0.1:8765`（`config.toml [web] port`）

### Web 控制台结构

```
┌ Tab：当前会议 │ 面试帮助 │ 声纹登记 ─────────────────────────────┐
│ ┌ 左栏 ────────┐ ┌ 中栏 ──────────────┐ ┌ 右栏 ────────────────┐ │
│ │ 当前会议人数 │ │ 录音计时 / 状态     │ │ 标注（笔记/重点/注释）│ │
│ │ [开始录音]   │ │ 实时转写(滚动)      │ │ 发言归纳（选发言人→LLM）│ │
│ │ 历史会议列表 │ │ 会后最终转写        │ │                      │ │
│ │ (标题·编辑·删除)│ │ 对话行带标注图标  │ │                      │ │
│ └──────────────┘ └────────────────────┘ └──────────────────────┘ │
└──────────────────────────────────────────────────────────────────┘
```
【事实】三栏各自滚动（≥1041px）；【事实】声纹登记曾在左栏，阶段 9 拆为独立 Tab；Tab 顺序为 当前会议 / 面试帮助 / 声纹登记。

## 6. 能力清单与产品行为

### 6.1 录音
- 16 kHz 单声道 16 位 wav；零时长/全程静音不调用模型，文字稿写"（未识别到语音）"。
- 启动前至少 1 GB 可用磁盘；麦克风打不开给中文提示且不留空目录。
- 静音警告、音量条；崩溃后 wav 头长度不准仍能读出已写入采样。
- 打开麦克风带 15 秒超时，超时提示"打开麦克风超时（系统音频卡住了），请重启服务后重试"。
- 停止后压缩 m4a。
- 开始新录音时清空上一场选中行和转写区残留。

### 6.2 实时转写
- 默认关（CLI `--live`）；Web 控制台里是录音时的中栏实时视图【推断】。
- 句子级：VAD 切句 → 逐句 Whisper → 输出 `[HH:MM:SS] 文字`（无说话人标签，因为说话人是会后做的）。
- 积压上限 5 句，满时丢最旧并整场只警告一次；停止时最多等 10 秒冲出尾句。

### 6.3 会后转写与说话人
- Whisper `large-v3-turbo`，语言 zh，不传 initial_prompt。
- 说话人区分默认开，人数自动或由用户填"当前会议人数"（1–20）。
- 匿名标签 `说话人A…Z`，之后 `说话人27`；行格式 `[HH:MM:SS] 说话人A: 文字`。
- 产出 `transcript.md`，表头含 `- 说话人：` 行（发言归纳以此为解析门槛）。

### 6.4 声纹
- **登记**：现场录制（弹出朗读文案弹窗，完成自动关闭；关闭/Esc 取消）或导入音频；存 512 维向量，JSON，权限 600，不存音频。
- **名字规则**：字母/数字/中日韩文字/`_`/`-`，1–20 字，不得以"说话人"开头。
- **识别**：会后把匹配片段的匿名标签换成名字。
- **现状**：阈值 0.5，**未校准**【缺口】。
- **新设计（reliability-first，待实现）**：`[voiceprint] high/low` 双阈值；≥high 直接写名字，low~high 写"疑似张三"，<low 保持匿名；分数写在新表头行 `- 声纹匹配：`。
- **删除"同意勾选"**（阶段 11）：只保留"明确替换同名声纹"确认【缺口，见 §10】。

### 6.5 标注
- 类型：📝笔记 / ⭐重点 / 💬注释；带时间（允许多位小数）；存会议目录 `annotations.json`。
- 标注在中栏对应对话行打图标；点右栏记录，中栏滚动并定位。

### 6.6 历史会议管理
- 目录 `~/Meetings/YYYY-MM-DD_HHMM`（重名加 `_2`）；行内：点击打开、"编辑"改标题（存 `meta.json`，目录名不变）、"删除"（原生 confirm）。
- 转写行左对齐，换行缩进等于时间标记宽度。
- 会后转写状态着色：idle / running / completed / failed。

### 6.7 发言归纳（LLM）
- 选当前会议的某位发言人 → 其全部发言交给 LLM → 返回归纳；支持自定义提示词（高级）。
- 发言来源仅限最终稿；超过 `max_input_chars`（60000）直接 413；未配置 `[llm]` 用到才 503。
- 按名字聚合（"疑似张三"归到张三下，新设计）。

### 6.8 面试帮助
- **职位库**：类型仅 前端/后端/客户端/测试；标题 ≤100 字，要求 ≤10000 字；存 `~/.config/meeting-recorder/jobs.json`。
- **候选人简历**：文字 ≤20000 字，或粘贴截图 ≤5 张（png/jpeg/webp/gif，单张 ≤5MB）；简历与结果**不落盘**。
- **输出**：约 40 分钟，三维度——专业能力≈20 分钟、AI 应用≈12 分钟、开放性问题≈8 分钟；每题含预计用时、考察点、**答案要点**（2–4 条，每条一句）；Markdown 渲染（marked + DOMPurify 白名单）。

### 6.9 可信度优先（规划中）
| 项 | 用户看到的 |
|---|---|
| 自检页 doctor | 只读检查：模型是否到位、[llm] 是否配齐、麦克风枚举；响应不含绝对路径和设备序列号；"测试连接"按钮只回"通/不通 + 固定中文原因" |
| 录音隔离 | 先 spike（常驻麦克风流 / abort() / 子进程），避免 CoreAudio 卡死拖垮整个服务 |
| 中断恢复 | 历史列表出现"未完成"标记；可补转写；已有 transcript.md 的不碰；"重新转写"先备份为 `transcript.md.bak` |
| 离线评估 | `tools/eval_voiceprint.py`：FAR/FRR、推荐高低阈值、DER；样本不足提示"置信有限，阈值仅作初值" |

## 7. 核心用户流程

**流程 A：开会 → 回看**
```
打开 Web → 填人数(可选) → 开始录音 → 中栏实时转写 + 随手打标注
→ 停止 → 压缩 m4a、后台会后转写（状态着色）
→ 最终稿出现，匿名标签 / 真名 → 选发言人 → 发言归纳
```

**流程 B：首次使用声纹**
```
声纹登记 Tab → 输入名字 → 现场朗读文案（弹窗）或导入音频
→ 保存向量 → 之后每场会议自动尝试认人
```

**流程 C：面试**
```
面试帮助 Tab → 选/建职位 → 粘贴简历文字或截图 → [推荐]
→ 40 分钟问题单 + 答案要点 → 面试时用"当前会议"录音和标注
```

**流程 D：崩溃恢复（规划）**
```
重启服务 → 历史里看到"未完成" → 点补转写 → 生成 transcript.md
```

## 8. 数据与隐私模型

| 数据 | 位置 | 是否出本机 |
|---|---|---|
| 音频 meeting.wav / .m4a | `~/Meetings/<会议>/` | 否 |
| 转写 transcript.md、live.txt | 同上 | 仅发言归纳时发文字给 LLM |
| 标注 annotations.json、标题 meta.json | 同上 | 否 |
| 声纹向量 | `~/.config/meeting-recorder/voiceprints/*.json`（600） | 否 |
| 职位库 jobs.json | `~/.config/meeting-recorder/` | 生成问题时发给 LLM |
| 简历文字/截图 | 不落盘 | 点"推荐"时发给 LLM（图片先经识别） |
| 模型缓存 | `~/.cache/meeting-recorder/models/` | 首次下载来自网络 |
| API Key | `config.toml [llm]` | 只用于请求 LLM，不回显 |

安全边界：只绑 127.0.0.1；变更类路由走 Origin 守卫，JSON 体要求 `application/json`（否则 415）；所有文本用 textContent 渲染（面试结果经 DOMPurify 是唯一例外）；LLM 请求不跟随重定向。

## 9. 产品演进脉络（反推出的路线）

```
CLI 录音/转写 → 说话人 → 实时 → 声纹 → Web 台 → 体验打磨(6-9)
→ LLM 归纳 → 面试助手 → 稳定性修复(13) → 面试增强(14)
→ 【可信度优先】自检/恢复/声纹分档/评估
```
**判断**：产品从"录音转写工具"一路长成"会议 + 面试的个人助理"。最后一轮（reliability-first）明确在回头偿还信任债：它在 non-goals 里列出"拆分面试助手、跨会议搜索、纪要、待办、本地 LLM 预设"，说明作者已意识到范围蔓延，决定先稳底盘。

## 10. 产品缺口与风险（逆向发现，请重点审阅）

1. **声纹阈值未校准**（阶段 4 Task 8）：0.5 是拍的值，认错人会直接把别人的话归到真名下。双阈值设计缓解，但需要真实数据（≥2 场、每场 ≥3 人）才能最终定值。
2. **说话人区分效果未验收**（阶段 2 Task 5）：没有真实会议评估，DER 脚本已有，数据没有。
3. **去掉声纹同意勾选**：录的是别人的声音，登记的是别人的声纹。产品上没有任何同意留痕；这对个人本机用途可接受，但若录面试候选人或同事，有合规/伦理风险。隐私文案修正已标 TODO。
4. **"音频始终不出本机"口径需精确**：面试截图和文字会发给 LLM 端点，模型首次要联网下载；对外表述应是"音频与声纹不出本机"，不是"一切不出本机"。
5. **CoreAudio 卡死是系统级风险**：15 秒超时只是止血，真正隔离方案还在 spike；卡死后只能重启服务。
6. **面试助手与会议录音是两个产品**：职位类型写死四类，题型含"AI 应用"，明显针对软件岗位招聘。放在同一 Tab 体系里有范围蔓延风险。
7. **发言归纳依赖最终稿**：录音中、转写失败时无法使用；未完成会议看不到发言人列表。
8. **无多用户/无认证**：本机其他进程可访问 127.0.0.1:8765；Origin 守卫挡的是浏览器跨站，不挡本地恶意进程。
9. **文件即状态的代价**：靠"有 wav 无 transcript.md"推导未完成，无法区分"转写中/失败/被取消"，失败原因无处记录。
10. **阶段 13、14 仍未提交**，台账显示工作区脏。

## 11. 成功标准（反推）

| 维度 | 可观察指标 |
|---|---|
| 可靠 | 一场录音从开始到出稿不丢数据；崩溃后可补转写；系统音频卡住时有明确提示 |
| 准确 | 登记用户被正确标名的比例高、冒名认错率（FAR）≤1%（high 阈值目标）；灰区冒名率≤10%（low 阈值目标） |
| 隐私 | 抓包验证：音频、声纹无外发；LLM 请求只在点击后发生 |
| 易用 | 开始录音 ≤2 次点击；转写完成后无需手工整理即可回看 |
| 降级 | 关掉任一增强（区分/声纹/LLM/实时），录音和基础文字稿结果不变 |

## 12. 明确不做（从 non-goals 汇总）

云同步与账号体系；远程访问；Windows/Linux；跨会议全文搜索；自动会议纪要/待办；本地 LLM 一键预设与隐私界面（暂缓）；`status.json`；transcript.md 表头改 YAML/JSON；自动测试使用真实音频。

## 13. 待你确认的问题

1. 目标用户是**你自己一个人**，还是未来想给同事/团队用？这决定声纹同意、认证、安装门槛是否要重做。
2. **面试帮助**是长期核心，还是会拆出去的副线？（reliability-first 把"拆分面试助手"列为不做，但没说以后）
3. 对**被录音的人**：是否需要在产品里提示"正在录音"、保留告知记录？
4. 第一优先级是**准确（认对人）**还是**可靠（不丢录音）**？现有路线图两者并行，但数据到位前只能先做后者。
5. 本文把"实时转写"在 Web 里当作标配，若实际是可选开关，请纠正。
