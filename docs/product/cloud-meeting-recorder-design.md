## 1. 产品定位

让用户通过 HTTPS 网站登录个人工作空间，无需启动本地 Python 服务，即可记录自己及线上会议对方的声音，得到带时间戳与说话人信息的文字稿，并完成标注、归纳和面试准备。

**价值顺序：不丢录音 > 不串用户 > 结果可核对 > AI 增强 > 视觉表现。**

“speaker”在本文中指用户电脑正在播放的声音，不指云服务器设备，不指用麦克风重新拾取扬声器外放。戴耳机时也应能在支持环境中采集对方声音。回放时使用用户电脑的扬声器或耳机。

### 1.1 目标用户与场景（建议）

面向中文使用者、会议记录者、技术面试官及需要回看发言的人。不是多人实时协作平台。

- 线上会议：自己的麦克风 + 会议软件播放声音，实时查看文字并标重点。
- 现场会议：明确选择“仅麦克风”，不要求无用的系统音频授权。
- 面试前：维护职位，粘贴简历或截图，生成约 40 分钟面试题。
- 会后：回放录音、查看最终文字稿、按说话人归纳、处理失败任务。
- 声纹：经授权采集熟悉人员声纹，在个人记录中辅助识别。

### 1.2 首版目标与非目标

首版：账号、个人空间、双音源录音、可靠上传、现有业务功能、私人回放、异常恢复和必要设置。

不默认纳入：团队共享、协同编辑、公开链接、收费订阅、会议机器人、实时面试答案、原生 App、浏览器扩展、辅助客户端、旧数据自动迁移。若纯网页无法覆盖必须支持的音源，重新确认范围，不能擅自要求用户安装软件。

## 3. 核心用户流程

### 3.1 首次使用

访问网站 → 登录 → 阅读云端数据处理说明 → 进入空白个人空间 → 创建录音 → 选择录音模式 → 浏览器授权 → 音源检查 → 开始。

未登录不请求麦克风权限。普通用户不需要配置模型 Key。注册与登录机制见第 17 节。

### 3.2 双音源会议

1. 选择“双音源：麦克风 + 电脑播放声音”，填写标题、预计人数 1–20，选择实时转写。
2. 请求麦克风权限；由单独用户点击触发共享选择器。
3. 引导选择符合环境的标签页/屏幕及共享音频，不代替用户选择共享对象。
4. 检查实际音轨、显示两个输入音量；音轨存在但没有能量时提示检查会议是否在播放。
5. 两个音源可用后开始；任一失败时不冒充双录成功。
6. 可明确选择“继续仅麦克风”作为降级，也可取消；降级录音带单音源标记。
7. 录音中看计时、实时文字、标注和上传确认位置。
8. 停止 → 尾片上传 → 完整性确认 → 排队 → 最终转写/说话人/声纹 → 查看。

### 3.3 回看与恢复

历史列表 → 选择记录 → 播放并定位文字/标注 → 全场或指定说话人归纳。

转写失败：录音保留 → 补转写。已有稿重转写：新建版本 → 成功后切换当前版本；失败保留旧稿。

刷新/关闭网页将中止浏览器采集。重新打开后展示已上传部分及可恢复的本机暂存片段；恢复上传与重新授权继续录音是两件不同的事，缺失时间段必须可见。

## 4. 信息架构与页面交互

保留“当前会议 / 面试帮助 / 声纹登记”的主要导航，增加账号菜单和设置；不加入社交或团队入口。

- 活动录音条在切换业务页面时保持可见，离开当前会议页不停止采集。
- 浏览历史时不能将历史内容误认为当前实时稿；明确标注当前记录和活动录音。
- 人工滚动时暂停自动追尾，提供“回到最新”。
- 录音中不能播放当前记录以避免回录；回放历史记录时提醒可能被系统音源录入，不默认自动播放。
- 删除和覆盖采用明确确认；处理中记录建议禁止改名/删除，或允许取消后删除，不静默破坏任务。
- 首版不默认提供文字稿手工编辑或标注编辑/删除；如增加需作为增强明确验收。

### 4.2 登录与空状态

登录页只承诺已验证的能力，说明云端处理和私人空间。支持登录中、认证失败、过期、服务异常状态；错误不泄露账号是否存在。空状态显示“创建第一条记录”，不是无意义统计仪表盘。

### 4.3 面试帮助

职位列表 → 职位类型/名称/要求编辑 → 简历文字与截图区域 → 生成 → 约40分钟问题清单。页面常驻提示“简历与问题不保存为历史”。离开/刷新可能失去临时内容；不假称永久保存。

### 4.4 声纹登记

声纹列表（姓名、模型/登记状态） → 姓名 + 授权确认 → 朗读弹窗 → 音量/倒计时 → 处理 → 完成。关闭/Esc/取消立即释放麦克风并取消本次任务，不保存未完成声纹。替换同名需要二次明确确认。

### 4.5 设置与自检

账号、隐私政策、数据删除说明、音源能力检测、上传连接、云端处理可用性。用户看不到服务器文件路径和底层密钥。测试模型连接由平台限流，不能变成用户任意外网请求工具。

## 5. 浏览器音频规格与兼容策略

### 5.1 音源语义

- 麦克风：浏览器 getUserMedia 请求用户输入设备。
- 电脑声音：浏览器 getDisplayMedia 获取经用户选择的共享音频；systemAudio 等选项是提示，不保证得到音轨。
- 播放：浏览器音频播放器；输出设备选择仅在支持 setSinkId 等能力时出现，否则使用系统默认。
- 不用声纹音源标签替代说话人：共享音频可能包含多人，现场麦克风也可能包含多人。

### 5.2 共享画面边界

getDisplayMedia 通常要求视频轨，不能用 video:false 假定可进行音频专用授权。界面提前说明可能需要选择屏幕/窗口/标签页，但本产品只处理并上传音频。

共享视频帧不得编码、上传、入存储或进入日志。视频轨是否必须维持以保持音频，由实机探针确认；如果保留，说明其仅用于浏览器共享会话。不承诺所有环境能立即停止视频轨仍保留音频。

共享权限每次由用户操作触发；不能绕过浏览器选择器或假设授权可永久保存。标签页的共享声音不等于全系统音频；采集实际路由到耳机的声音也取决于环境，不以设备名称作成功依据。

### 5.3 支持矩阵（验证计划，不是兼容性声明）

| 环境 | 麦克风 | 浏览器会议标签页音频 | 桌面会议软件/全系统音频 | 回放 |
|---|---|---|---|---|
| Windows + Chrome/Edge | 首要验证 | 首要验证 | 首要验证，必须验证共享对象/权限 | 首要验证 |
| macOS + Chrome/Edge | 首要验证 | 首要验证 | 高风险验证，不能承诺全系统采集 | 首要验证 |
| macOS + Safari | 待验证 | 待验证，不作为首版双录保证 | 待验证，不作为首版双录保证 | 待验证 |
| Windows/macOS + Firefox | 待验证 | 待验证，不作为首版双录保证 | 待验证，不作为首版双录保证 | 待验证 |
| Linux 桌面 + Chrome/Edge | 后续验证 | 后续验证 | 后续验证 | 后续验证 |
| 手机/平板 | 首版不保证录音 | 不保证 | 不保证 | 建议允许响应式查看/回放，需验证 |

每项实测记录 OS 版本、浏览器版本、会议软件版本、共享对象、外放/耳机、是否有音轨、是否有正确声音、持续时长、异常行为。未测项标“待验证”，无音轨标“不支持当前组合”。

### 5.4 音频处理建议

分别保留麦克风和电脑声音原始音轨，采用共同单调时间轴及每段起止时间。云端解码、重采样至模型需要的 16kHz 单声道工作音频；浏览器源采样率不强行假定16kHz。输出可生成混合回放文件。

MediaRecorder 编码格式动态检测；各音轨片段可能依赖头部/前片段，不假定每个 blob 都是可独立解码文件。必须验证实时解码链路；若不能满足延迟，评估 AudioWorklet PCM 流的成本。具体采集方案由原型选择。

不将两路叠加后永久丢弃原轨。对齐漂移、静音、重叠发言、回声抑制和音源结束都要实测。推荐耳机降低重复拾音，但不能用“戴耳机”代替数字系统音频采集能力。

参考：[MDN getDisplayMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getDisplayMedia)。本次核对的文档指出系统音频选项可能被浏览器忽略，且受操作系统限制；这不是本项目实机测试结论。

## 6. 账号、权限与多用户规则

### 6.1 认证建议

首版建议托管身份服务或成熟认证组件，优先邮箱验证码/一次性链接；密码和第三方登录待确认。不自研密码学。使用服务端验证的会话，Cookie 采用 HttpOnly、Secure、合适 SameSite；同源变更请求有 CSRF 防护。身份令牌不放 URL。

用户身份由认证上下文注入，拒绝业务请求任意指定 owner_user_id。注册开放/邀请制、账号找回与注销由第17节确认。

### 6.2 全链路隔离

会议、音轨、片段、文字稿、标注、总结、职位、声纹、上传会话、处理任务、事件流、缓存和临时简历都绑定 owner_user_id。

数据库查询强制用户条件；可用行级策略作为纵深防御，但不能取代业务鉴权。外部资源 ID 不作为秘密或权限凭据。私有对象存储不得裸露公共链接；优先认证代理支持 Range 回放。若采用短时签名地址，说明其有效期内持有者可访问，且删除/注销的即时撤销不天然保证，需要额外机制。

SSE/WebSocket 订阅前校验资源归属，连接过期/账号撤销时关闭；事件只含用户自己的内容。上传恢复与事件恢复独立设计：事件带资源版本/游标，断线、切换实例或服务重启后从持久任务状态/文字稿快照重新同步；历史游标失效时回全量本人快照，不依赖原控制器内存事件。缓存键包含用户和资源版本。后台任务重新校验有效用户、归属、资源删除状态，不信任任意队列消息。

跨用户资源统一返回不泄露存在性的404或等效响应。列举接口仅本人数据；下载、版本、标注、声纹任务取消同样检查，不仅保护详情页。

### 6.3 并发与账号切换建议

不同用户允许并行录音。每账号建议只允许一场活动采集，通过服务端租约与浏览器跨标签页通知防重入；不同账号互不阻塞。租约失效表示失联，不等于已安全完成。

显式退出/换账号：先提示停止并上传尾片；若用户选择放弃未上传内容，明确风险后清理。清除页面、媒体资源、事件连接和用户缓存，禁止把旧片段归到新账号。

会话自然过期：服务端停止受保护上传；浏览器提示重新认证，可短时本机暂存，重新登录同一账号才可恢复上传。不同账号登录时不展示旧内容，隔离暂存并要求正确账号认证。服务端已收到的音频可继续处理，客户端不再收到私人事件。

## 7. 录音可靠性与状态模型

### 7.1 三套独立状态

采集：idle → requesting_permissions → ready → recording → stopping → stopped；异常可进入 interrupted。

上传：pending → uploading → buffered_offline → uploading → finalizing → complete；不可恢复进入 partial/failed。

处理：not_submitted → queued → transcribing → diarizing → matching_voiceprints → completed；失败分 basic_failed 与 completed_with_warnings。

不要把“正在录音”和“正在处理”混成一个状态；一个音源结束不能掩盖另一音源仍采集。界面显示录制位置、连续已确认保存位置、待上传大小和故障原因。

### 7.2 片段与完整性

每片段记录 upload_session_id、capture_epoch_id、track_id、sequence、start_ms、end_ms、checksum、codec。刷新或重新授权后的采集建立新epoch，结合服务端清单、会议起始时间与恢复时的时间锚点确定相对偏移；同epoch两轨使用同一单调时钟，跨epoch保留真实中断区间和时钟不确定性，不用新页面performance.now直接拼接，也不把中断压缩成无缝音频。相同幂等键与相同哈希重试只确认一次；哈希冲突拒绝。服务端持久保存并记录片段后才回 ACK。

“已保存至”取连续已确认时间段，不取任意最大序号。上传完成提交轨道清单及尾片，核对顺序、缺片、长度和校验；不得缺片仍宣布完整。允许将不可补的部分保存为部分录音，标出缺失区间。

索引暂存建议用浏览器 IndexedDB，按用户与录音隔离，ACK后清理；不被 Service Worker 公共缓存。浏览器存储可能被系统清理，不承诺崩溃一定恢复。

恢复窗口内建议允许同账号补传和以新epoch继续，窗口到期由后台扫描器依据已持久ACK片段自动部分封口；部分资产允许回放及明确标记缺口的转写。已ACK且归属有效会议的片段必须保留，不能因租约/上传会话超时当孤儿删除；只有无有效归属或无有效引用的对象才进入孤儿清理。封口后不继续追加，后续新录音另建会议。

### 7.3 异常行为

| 异常 | 产品行为 |
|---|---|
| 拒绝麦克风 | 不开始录制；展示权限恢复步骤 |
| 系统音频无轨 | 不标双录成功；明确确认后单麦继续 |
| 共享停止 | 提示电脑声音已停止；记录区间；继续另一轨或用户停止 |
| 无音量 | 提示检查音源；不把静音自动判为权限失败 |
| 短时断网 | 本机暂存；上传重试；显示云端保存落后 |
| 暂存容量不足 | 提醒停止/恢复网络；必要时停止采集，不静默丢片 |
| 刷新/关闭 | 尽力尾片处理但不保证；采集中止；已上传不丢 |
| 休眠/崩溃 | 恢复后标中断；不能假装持续录音；允许补传已有片 |
| 实时转写落后 | 暂停/跳过实时增强，保留音频供最终稿 |
| 云端转写失败 | 音频仍可回放；任务重试/补转写 |
| 说话人/声纹失败 | 基础文字稿保留，以匿名/未区分方式降级 |
| 平台重启 | 持久队列重取，任务幂等；不依赖内存线程 |

### 7.4 待压测参数（建议，不是承诺）

采集片段目标约2–5秒；正常网络连续保存落后目标≤10秒；实时文字典型目标5–15秒；本机未上传缓存目标最多5分钟或100MB，以先达到者触发提示/停止策略；会话最大时长建议首版2小时；同账号活动录音1场。上线前根据编码、设备、网络和模型评估调整。

最终转写耗时、同时在线用户和GPU数量不能在缺乏负载与预算时给出保证。页面展示可测的阶段而非虚构倒计时。

## 8. 文字稿、说话人与标注

- 保留中文为主、中英混合内容与时间戳；繁简行为与当前实现一致，模型更换后回归。
- 实时稿为临时结果，不默认实时完成声纹实名识别；最终稿可能改段落和标签。
- 人数提示1–20，未填则自动估计；不保证重叠发言的完美区分。
- 文字段使用稳定版本 ID + start_ms/end_ms；显示格式保持可读。
- 标注保存相对会议开始时间及类型/内容；不绑字幕行号或字幕文字，重转写仍可定位。
- 归纳和标注定位必须显示所用文字稿版本，旧版本不被失败的新稿覆盖。
- 无语音写“未识别到语音”，不可被模型幻觉当正常会议纪要。

## 9. 声纹规格与数据责任

登记：姓名校验、用户授权声明、朗读采集、质量检查、提取、确认保存。替换需要明确确认并原子切换；失败保留旧模板。导入能力若保留，应改为浏览器文件上传，不接受用户指定服务器任意路径。

声纹仅在本人库匹配，不建全平台声纹库、不用于登录。高阈值姓名、低阈值疑似、其余匿名；阈值需随模型校准，不能照搬当前0.5/0.35并宣称已校准。

保存特征、模型 ID/版本、权重摘要、维度、采样率、预处理/归一化版本、阈值校准版本、采集时间及授权记录。现有512维模板不能仅凭维度相同就跨模型使用。建议保持兼容模型，若更换则重新登记或经授权原样本迁移；模型异构模板不混算。

建议提取成功后清除原始登记录音；失败/取消也清理临时样本。实际清理期限见第12节。删除模板后新识别不得使用；在途任务输出前检查模板版本/撤销状态。已生成文字稿建议保留当时姓名标签，并提示删除声纹不自动匿名历史；若要求撤回历史标签，单独设计重处理。

用户负责取得被录音/登记人员的适当授权；平台提供提示、删除入口与政策。适用地区的声纹敏感信息和录音规则需法律确认，文档不构成合规认证。

## 10. 总结与面试帮助

### 10.1 总结

用户主动发起，全会议或指定说话人，输出摘要、要点、待办、决议；负责人未知写待定、无决议写无，不编造。疑似身份保持说明。文本中的指令是资料，不执行。

建议总结持久保存为会议派生版本，绑定 transcript_version_id、说话人范围、模型与生成时间；这是新增持久化行为，待确认前默认只临时返回结果。超长内容明确拒绝或提供经确认的分段归纳，不能静默截断。

### 10.2 面试

保留职位类型（前端/后端/客户端/测试）、名称、要求的增改删。简历文本≤20000字；图片最多5张、单张≤5MB，png/jpeg/webp/gif，验证真实内容、解码尺寸与请求总预算，不仅扩展名。

截图可先由多模态模型提取文字，再结合粘贴文本生成。约40分钟：专业20、AI应用12、开放8；每题包括预计用时、考察点、2–4条答案要点。简历为空则按职位要求出题。

首版延续简历与面试结果不持久保存：不创建候选人库、不入备份、不记录全文日志、不写持久业务队列。建议短生命周期隔离执行器；断开/超时后清理。若要离开页面仍能恢复面试结果，需明确短期加密缓存及保留窗口，这会改变“不保存”的含义，不能暗中开启。

所有AI结果经安全Markdown渲染与HTML净化，禁止危险URL；对输入与输出做长度限制。LLM错误只给固定安全原因，不返回服务商原文/Key。

## 11. 架构方案比较与推荐

| 方案 | 优点 | 成本/风险 | 结论 |
|---|---|---|---|
| 现有服务直接公网化，加登录 | 看似改动少 | 仍采服务器设备、共享全局状态、Apple依赖、无可靠多租户 | 排除，不满足核心目标 |
| 保留Python业务逻辑，云端API+私有存储+任务worker+浏览器采集 | 复用归纳/标注/声纹/转写抽象；边界清楚 | 音频采集、存储、调度必须改造 | **推荐建议** |
| 全面托管ASR/说话人服务 | 上线与伸缩容易 | 音频出平台、成本、供应商锁定、声纹语义变化 | 作为备选，需隐私与质量批准 |

不为迁移而重写全部前端：可先模块化现有原生JS，复杂性需要时再评估框架。本文视觉规范不要求特定框架。

### 11.1 推荐逻辑架构

~~~text
用户浏览器：认证UI / 双音源采集 / 本机暂存 / 标注 / 音频回放
        ↓ HTTPS鉴权API与片段上传    ↑ 私有SSE任务事件
API服务：身份、归属校验、限流、上传清单、会议/职位/标注
        ├─ PostgreSQL：用户关联、会议元信息、版本、任务状态
        ├─ 私有对象存储：音轨、片段、最终回放资产
        └─ 持久任务队列 → 音频worker → ASR/说话人/私有声纹
                                  → 文字稿版本/状态
文本增强服务 → 平台LLM适配器 → 总结或临时面试结果
~~~

推荐 FastAPI + PostgreSQL + S3兼容私有存储；队列实现选成熟持久机制，Redis若采用必须配置持久化/恢复策略，不把内存pubsub当任务真相。普通API不做GPU长推理。音频编码使用云端可部署转换工具替代macOS专用工具。

mlx-whisper 不作为通用Linux默认推理引擎；保留 transcribe_fn 等适配入口，评估 faster-whisper 等Linux引擎或托管服务。更换引擎时比较时间戳、中文、重叠语音和声纹质量，不承诺输出逐字相同。

ASR、说话人、声纹适配器只接授权数据路径/流，不接客户端任意本机路径。服务器下载模型由部署预热完成，录音关键路径不临时下载大模型。部署探针必须记录Linux发行版、CPU架构、Python版本、CPU/GPU后端、CUDA/驱动、音频解码工具、VAD与说话人/声纹ONNX运行时、模型缓存及许可；验证离线冷启动、常驻内存和多任务容量，不只验证import成功。

### 11.2 任务隔离与幂等

音频任务携带 task_id、owner_user_id、meeting_id、input_version、generation。执行前/输出事务前核对所有关联、删除墓碑及版本。重复消费不重复发布；新重转写任务不能被旧任务晚完成覆盖。删除与结果发布通过事务/代次检查避免复活。

实时推理单独限流，最终转写公平排队，增强服务故障不阻塞上传。后台模型进程可复用权重，但用户音频、缓存、识别状态不跨任务残留。

| Annotation | meeting归属、offset_ms、类型、内容 |

### 12.2 保留策略（建议值，需确认后成为政策）

| 数据 | 建议保留 | 删除规则 |
|---|---|---|
| 会议音频/文字/标注 | 用户删除前；配额规则待定 | 权限立即失效，后台实体清理目标24小时内 |
| 总结 | 若确认持久化，随会议 | 同会议级联；删除后旧任务不得恢复 |
| 声纹特征 | 用户删除前 | 立即停止新匹配；清理及备份按政策 |
| 声纹原始采样 | 仅提取期间 | 成功/失败/取消后清理，目标1小时内兜底 |
| 简历图片/文字与面试结果 | 请求生命周期，不做历史 | 完成/失败/取消立即清理；临时残留1小时兜底 |
| 未完成上传 | 建议24小时恢复窗口 | 到期标部分录音，清除孤儿片段 |
| 浏览器暂存 | ACK后立即清；同账号恢复 | 显式放弃清理；退出按第6节；不保证永久保存 |
| 运营日志 | 建议30天，无业务正文 | 到期清除；访问审计另定 |
| 备份 | 建议最长30天滚动 | 不能承诺即时物理删除；恢复必须重放删除墓碑 |

“用户删除立即无法访问”与“所有介质立即物理清除”是不同承诺。第三方服务的保留/训练/删除政策单独披露，不承诺平台无法控制的删除。账号注销停止新任务并级联清理；是否提供业务导出与注销等待期待确认。

## 13. API边界建议

非最终接口契约，所有私人接口统一认证与owner检查。音频事件与文件访问不例外。

- 认证：session查询、登录/退出、找回/注销（方式待定）。
- 会议：本人分页列表、创建、详情、改名、删除。
- 上传：创建会话、按音轨提交片段、查询连续ACK、提交清单完成、取消。
- 录音租约：持有/心跳/释放；不让远端API直接控制用户麦克风。
- 处理：提交最终/补/重转写，任务查询/取消，认证事件流。
- 文字稿：版本列表、版本详情、当前指针；音频认证Range回放。
- 标注：列表/添加，归属会议和相对时间。
- 声纹：列表/上传采样/创建提取任务/替换/删除/取消。
- 职位：本人列表/创建/更新/删除。
- 总结：基于指定文字稿版本和说话人范围生成。
- 面试：职位+临时简历生成，不误用持久任务队列保存敏感全文。

错误语义：401未认证；404资源不可访问；409状态/版本冲突；413大小超限；429限流；安全的5xx服务失败。前端不能把失败转成成功toast。长任务返回任务ID与状态，而非同步阻塞到HTTP超时。

## 14. 安全、隐私与运维

- 全程TLS；私有对象存储与数据库加密；声纹特征按敏感数据保护，密钥轮换。
- 平台Key不进浏览器、不进响应、不进日志；限制外部AI地址配置，防SSRF。
- CSRF、XSS、恶意Markdown、文件伪装、解码炸弹、路径穿越和越权纳入测试。
- 上传大小、时长、每用户并发、AI调用与失败重试限流，防止单用户耗尽GPU/磁盘。
- 认证日志不含验证码；运营日志不含录音/简历/文字稿正文、声纹向量或敏感URL。
- 录音和云端AI处理说明包含音频是否发送第三方、部署地区、保留期限和删除限制。
- 管理员首版只查看健康/容量等必要信息；业务数据访问如确有必要，走明确授权、最小权限与审计，不能有隐式全量浏览入口。
- 运维指标：上传失败/ACK延迟、缓存压力、缺片比例、队列等待、处理失败、声纹降级、AI延迟、越权拒绝。不以敏感正文作为排障常规手段。
- 部署需预热模型、数据库迁移、健康/就绪检查、任务恢复演练、备份恢复及删除墓碑回放验证。

## 15. 视觉设计方向（建议稿）

完整视觉规范见 [DESIGN.md](../../DESIGN.md)。尚未确认，不覆盖本地版本现有样式。

方向：**可信录音工作台**。克制、阅读优先、状态可辨认，不采用营销式渐变/装饰卡片堆砌。

- 安全选择：保留三栏心智、固定录音状态条、正文高对比、熟悉的表单与危险操作确认。
- 差异选择1：双音源“信号轨”常驻，用户一眼看出录到什么；收益是真实能力可见，成本是占用顶栏空间。
- 差异选择2：长文字稿采用文稿式阅读节奏而非聊天气泡；收益是便于回看与核对，成本是降低聊天感。
- 差异选择3：显示“连续已保存位置”而非泛化绿色成功；收益是可信，成本是需要解释录制与保存差异。
- 色彩：深青绿主操作、暖灰底、红色仅录音/错误；两个音源用标签+线型+颜色共同区分。
- 字体：中文 Noto Sans SC；拉丁标题/正文 Source Sans 3；时间戳 JetBrains Mono，等宽数字。正式部署自托管授权字体；失败回退不阻塞录音。
- 4px基础间距、16px正文、明确焦点、最小44px关键点击目标；状态不只用颜色表达。
- 桌面宽屏三栏独立滚动；中屏标注抽屉；窄屏单栏分页，不通过压缩三栏导致不可读。
- 动效只解释状态变化，尊重减少动态效果偏好；计时与音量变化不造成整页频繁屏幕阅读器播报。

本轮根据现有产品与设计知识提出规范，没有进行竞品研究，也没有渲染视觉预览；不把文字布局当作视觉QA完成。

| AC03 | A/B同时录音与转写 | 音频、模型输出、事件与缓存无串用户 |
| AC04 | 同账号两个标签页开始 | 明确冲突与当前会话位置，不重复开启 |
| AC05 | 支持环境中双轨录音，本人/对方各读不同句子 | 两轨均含正确音频；戴耳机也能采对方；时间轴一致 |
| AC06 | 拒绝权限、无音轨、结束共享 | 中文指导正确；不假称双录；中断区间记录 |
| AC07 | 录音30秒，断网30秒再恢复；乱序/重复传片 | ACK真实，片段不重不乱；不可补缺口可见 |
| AC08 | 停止时丢尾片或伪造哈希 | 不标完整；可重传或部分保存 |
| AC09 | 刷新/崩溃/休眠后重开 | 不声称持续采集；已上传可找回；已有暂存只同账号恢复 |
| AC10 | 缓存达到限制、设备拔出、长录音 | 警告/停止行为符合规则，没有静默丢失 |

| AC12 | 重转写先后两任务乱序结束 | 当前版本不回退；旧稿与标注保留 |
| AC13 | 标注定位+音频回放+重转写 | 同一相对时间一致，不随行号漂移 |
| AC14 | A/B同名声纹；删除/替换/取消与在途识别 | 不跨库；撤销模板不继续新匹配；失败不毁旧模板 |

| AC20 | 键盘操作/窄屏/深浅色/减少动效 | 焦点可见、状态可读、文字不溢出、关键操作可达 |

假模型单元测试不能替代实机双音源录音，假DOM不能替代浏览器验收。精度测试用经授权标注语料，并报告字错率、说话人错误、声纹误识/漏识；没有数据前不指定虚构准确率。

### 16.2 最先验证的三件事

1. 音源探针：用户主要OS + 会议软件，在目标浏览器验证系统音频、耳机、两轨同步和持续录制。
2. 上传探针：编码连续性、实时解码、片段乱序、断网、刷新、尾片清单。
3. 模型探针：Linux部署、声纹模板兼容及中文质量/成本；明确比较“混合工作音频统一识别”与“分轨识别后合并”，产出选型、重复拾音去重及跨轨说话人簇合并方案。验收同一人跨轨不重复计为两人、重复拾音不产生重复文字、多位远端人员不被音源标签合并为一人，指定说话人归纳使用稳定会议级身份。

如果音源探针不覆盖必须使用的场景，先回到产品决策，不先开发全部功能再发现无法录对方。

### 16.3 建议实施阶段（非本轮执行）

P0 确认范围与完成三探针 → P1 登录/归属/存储/单麦可靠录音 → P2 双音源与回放/最终转写 → P3 实时稿/标注/声纹/总结/面试 → P4 隔离安全测试、性能、删除恢复与真实验收。

单麦只是开发阶段里程碑，不能替代已确认的双音源目标交付。每阶段有验收证据再进入下一阶段。本轮仅完成设计建议稿。
